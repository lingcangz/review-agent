# ADR-001：v1 只上传 diff 和按需上下文

- 状态：已采纳
- 日期：2026-09-14

## 背景

代码审阅需要理解变更，但将整个仓库上传到服务端或模型会扩大数据暴露范围、传输成本和无关噪声。首个版本的价值是对本次 Python 变更提供可证实的建议，而不是构建远程仓库镜像或介入合并流程。

## 决策

v1 必须提交 Git diff。审阅器只有在现有证据不足时，才能请求调用方明确提供、以仓库相对路径限定的最小文件上下文。CLI 在传输前读取 `.review-agentignore`、拒绝受保护路径并脱敏常见密钥。API 限制请求大小、校验相对路径，并且不记录源码或 diff。

发现必须锚定变更路径和行范围，并附有来自 diff 或获准上下文的具体证据。证据不足时，系统请求有限上下文或不报告问题。

## 后果

该决策减少敏感代码外发，并提高审阅输入的可解释性和成本可控性。它也会降低跨文件、跨模块推理的覆盖面，并可能增加一次补充上下文的交互。完整仓库上传、GitHub 集成和合并阻断均不属于 v1；若以后需要，必须通过新的 ADR 评估隐私、隔离和运行风险。
